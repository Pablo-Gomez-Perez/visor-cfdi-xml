# RF-007 — Importación masiva de CFDI XML

## Estado y límites

Implementación Java y Swing en `feat/rf-007-importacion-masiva-cfdi`.
**Requisito de despliegue:** instalar manualmente los procedimientos
`sp_rf007_importar_cfdi`, `sp_rf007_importar_pago`,
`sp_rf007_importar_nomina` y `sp_rf007_importar_retencion`
en la misma base MySQL del esquema canónico
`app/database/schema/visor_cfdi_mysql8_schema_v1.sql` antes de utilizar el módulo.
A petición del responsable de BD, **esta rama no publica ni instala el SQL**.
Un error «PROCEDURE ... does not exist» implica que falta ese paso, no que
Java deba crear procedimientos automáticamente. La nueva versión del SP
`sp_rf007_importar_cfdi` **reemplaza** a la anterior para soportar P y N.
La distribución SQL se entrega fuera de GitHub para instalación manual.

Firma exacta:

```sql
sp_rf007_importar_cfdi(
 IN p_lote_id BIGINT UNSIGNED,
 IN p_ordinal INT UNSIGNED,
 IN p_repositorio_id BIGINT UNSIGNED,
 IN p_clave_objeto VARCHAR(700),
 IN p_sha256_hex CHAR(64),
 IN p_tamano BIGINT UNSIGNED,
 IN p_nombre_archivo VARCHAR(260),
 IN p_ruta_origen VARCHAR(1024),
 IN p_cfdi JSON,
 OUT p_duplicado TINYINT UNSIGNED)
```

El SP no puede llamar a `COMMIT`, `ROLLBACK` ni gestionar una transacción
propia. La aplicación lo invoca con `Session.doWork` sobre la misma conexión
de un `EntityManager` y una transacción `RESOURCE_LOCAL` que abarca hasta
8 documentos. Ante fallo se revierte el lote actual completo; los lotes
anteriores permanecen confirmados. Esta es una decisión deliberada para evitar
transacciones de miles de documentos que consumen memoria, locks y redo logs.

## Alcance de extracción — segunda etapa

- CFDI 3.3 y 4.0 tipo **I, E, T, P y N** con timbre TFD 1.1.
- Pagos 2.0: cabecera, Totales, Pago, DoctoRelacionado, ImpuestosP,
  ImpuestosDR, impuestos de totales. Los montos usan decimal y no double.
- Nómina 1.2: cabecera, emisor, receptor, percepciones, deducciones,
  otros pagos, SubsidioAlEmpleo e incapacidades.
- Retenciones e Información de Pagos **2.0**: documento de clase
  `RETENCION`, emisor, receptor nacional o extranjero, período, totales,
  impuestos retenidos, documento relacionado, timbre.
- Se rechazan nodos especializados sin mapeo físico, por ejemplo
  `nomina12:HorasExtra`, `nomina12:CompensacionSaldosAFavor`,
  dividendos/intereses/pagos a extranjeros de retenciones y cualquier
  complemento adicional. El rechazo evita registrar un XML como completo
  mientras se pierden datos fiscales de sus complementos.
- La extracción **no verifica XSD, cadena original, firmas/sellos digitales,
  estatus SAT ni reglas fiscales de negocio**. Esos RF se desarrollan
  después con las versiones vigentes de catálogos.
- Nunca se construye un contribuyente propio a partir de terceros de XML.
- No se sobrescribe un UUID con otro contenido SHA-256. Los documentos
  se guardan fuera de MySQL en un repositorio SHA-256.

### Procedimientos para instalar manualmente (MySQL 8)

1. `sp_rf007_importar_pago(IN documento_id, IN JSON)`: inserción
   estructurada de `pago_fiscal`, `pago_fiscal_documento`, impuestos
   de pago/documento, totales e impuestos en moneda nacional.
2. `sp_rf007_importar_nomina(IN documento_id, IN JSON)`: inserción de
   nómina, emisor/receptor, percepciones, deducciones, otros pagos,
   subsidio e incapacidades.
3. `sp_rf007_importar_retencion(IN ... 9 argumentos ..., OUT duplicado)`:
   procedimiento específico para documentos de clase `RETENCION`
   con el **mismo contrato de 10 argumentos** del principal.
4. `sp_rf007_importar_cfdi(IN ... 9 argumentos ..., OUT duplicado)`:
   sustituir el procedimiento original; conserva I/E/T e invoca los SP
   especializados al importar documentos P/N nuevos.

Todos los procedimientos se llaman o encadenan en la misma transacción
de Java. No debe introducirse `COMMIT`, `ROLLBACK` ni abrir otra conexión.
Los procedimientos NO se publican en esta rama por solicitud expresa del
responsable de BD. Deben comprobarse primero en MySQL 8 con un juego de
datos de integración y una copia de seguridad.

## Concurrencia y recursos

- Dos tareas de lectura StAX y una cola de máximo cuatro futuros. Lotes de ocho documentos para acotar el uso de heap.
- Cada XML tiene un máximo de **8 MiB**; máximo 10 000 conceptos.
- Descubrimiento mediante `Files.walkFileTree`: sin lista general de archivos,
  sin seguir enlaces simbólicos y sin recorrer el repositorio destino.
- Directorio temporal específico de la ejecución; escritura por contenido
  SHA-256; comprobación de colisiones/corrupción.
- JDBC estrictamente secuencial con un `CallableStatement` reutilizado por
  transacción, evitando compartir conexiones y `EntityManager` entre hilos.
- Progreso agregado por lote en un `SwingWorker`; cancelación cooperativa.
- No se puede garantizar atomicidad física entre sistema de archivos y
  MySQL: un rollback puede dejar un XML huérfano en el almacén. Nunca se
  elimina automáticamente un objeto que podría estar siendo utilizado por
  otra importación. Incorporar posteriormente limpieza de objetos no
  referenciados y recuperación de lotes interrumpidos.

## UI / RBAC

`PanelImportacionCfdi` usa constructor vacío y `GroupLayout`,
instanciación explícita de componentes, sin E/S en el constructor.
Se abre desde «CFDI → Cargar XML» o el botón del encabezado.
Permite selección múltiple, carpetas y subcarpetas opcionales.
No ejecuta SQL en el EDT. El servicio exige `CFDI.IMPORTAR` y
asignación explícita `usuario_contribuyente` en cada transacción.

## Datos y auditoría

El procedimiento debe poblar al menos:
`archivo_documental`, `documento_fiscal`, `documento_participante`,
`documento_timbre`, `cfdi`, `cfdi_concepto`,
`cfdi_concepto_impuesto`, `cfdi_impuesto_totales`,
`cfdi_impuesto_global`, `cfdi_informacion_global`,
`cfdi_relacion_grupo`, `cfdi_relacion_uuid`,
`contribuyente_documento`, `documento_archivo`,
`importacion_archivo` y `bitacora_evento`, además de las tablas
`pago_fiscal*`, `nomina*` y `retencion*` según la familia.

Java crea `repositorio_documental`, `repositorio_local` y
`lote_importacion`, y actualiza el estado del lote. Errores que hacen
rollback dejan información diagnóstica en UI y estado del lote
(`PARCIAL` / `ERROR`); no garantizan una fila `importacion_archivo`
para el documento revertido.
