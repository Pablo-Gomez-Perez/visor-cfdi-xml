# RF-013 — Historial y archivado reversible de CFDI

## Alcance

CFDI → Historial de importaciones. Consultar por fecha de inicio (intervalo
inclusivo dd-MM-aaaa), contribuyente, usuario importador y estado histórico.
Los selectores usan únicamente titulares asignados y usuarios que importaron
para ellos. Paginación SQL de 100 filas con orden estable. El diálogo modal
presenta archivos aceptados, duplicados, rechazados o errores registrados,
UUID, ruta de origen, SHA-256, diagnóstico y estado operativo actualizado.

## Política de archivo

Se sustituye completamente la propuesta anterior de borrado físico.
No se borran lotes, archivos, documentos, vínculos, datos derivados ni XML.
Los contadores originales son independientes del nuevo indicador de CFDI
archivados (documentos distintos por lote). Los estados históricos de
importación nunca se modifican por archivar o restaurar.

La marca nullable `contribuyente_documento.archivado_en` pertenece al
vínculo titular–documento: NULL = activo, fecha = archivado. No se replica
en conceptos, impuestos, pagos o nómina. El UUID global, su XML y su vínculo
SHA-256 siguen intactos. RF-007 mantiene el control de duplicados y una
reimportación del mismo XML no reactiva un vínculo archivado. Un XML con
otro SHA para un UUID existente sigue sujeto al rechazo de RF-007.

- Archivar CFDI del lote: marca los documentos activos distintos de ese
  titular, aunque estén en varios lotes; no modifica otras cuentas fiscales.
- Archivar CFDI: marca el vínculo seleccionado en el detalle.
- Restaurar CFDI: desde cualquier ocurrencia histórica del titular, verifica
  tamaño, ubicación local canónica y SHA-256 del XML original del repositorio.
  Si falta, no coincide o existen originales ambiguos, no reactiva.
  No necesita el archivo de origen externo. No se reconstruyen datos porque
  el diseño conserva todas las filas fiscales; reparar datos corruptos o
  recuperar documentos previamente borrados está fuera del flujo.
- Archivar/restaurar exige lote cerrado, motivo 1–200 caracteres y permisos
  vigentes. Las operaciones idempotentes no duplican eventos. Se registra
  actor, titular, documento, lote, acción y motivo en bitacora_evento en la
  misma transacción. El archivado masivo usa SQL de conjuntos.
- RF-006 y RF-009 excluyen vínculos archivados en SQL. Las futuras consultas
  de cálculo deben aplicar la misma condición. Los vínculos a otros
  contribuyentes, pagos, obligaciones y relaciones administrativas se
  conservan; archivar no cancela un CFDI ni modifica su efecto fiscal legal.
  No es un criterio de deducibilidad, acumulación o acreditamiento.

## Permisos

| Permiso | Operación |
| --- | --- |
| IMPORTACIONES.CONSULTAR | Listar lotes y filtros |
| IMPORTACIONES.CONSULTAR_DETALLE | Detalle de archivos (requiere CONSULTAR) |
| IMPORTACIONES.ARCHIVAR_LOTE | Archivar vínculos activos del lote (requiere CONSULTAR) |
| IMPORTACIONES.ARCHIVAR_CFDI | Archivar vínculo seleccionado (requiere ambos de consulta) |
| IMPORTACIONES.RESTAURAR_CFDI | Reactivar vínculo verificado (requiere ambos de consulta) |

El servicio exige asignación explícita al titular, también para ADMIN.
ADMIN obtiene permisos realmente nuevos según bootstrap incremental; otros
roles requieren concesión explícita. Se retiran las claves anteriores
ELIMINAR_LOTE y ELIMINAR_ARCHIVO. RF-007/008/009 conservan sus permisos;
RF-011/012 no presentan operaciones independientes nuevas.

## Actualización de instalaciones

Antes de iniciar esta revisión, respaldar BD, detener la aplicación y ejecutar
una sola vez `app/database/migrations/20261116_rf013_archivado.sql`.
Los esquemas v1/v2 completos ya incluyen la columna para instalaciones nuevas
y pruebas; no ejecutar de nuevo la migración sobre ellos. DDL MySQL tiene
commit implícito. No aplicar el esquema completo a una BD existente.
La migración no restaura datos borrados por una versión anterior. No
modifica los procedimientos RF-007.

## UI y pruebas

PanelHistorialImportaciones usa panelEtiquetaHistorial, panelCentralContenedor,
panelSuperiorBotones, JTable y panelInferiorBusqueda con GroupLayout explícito.
El diálogo actualiza estado de lote junto con el detalle. Consultas y
verificación de XML en SwingWorker. Sin I/O en constructores. Pruebas MySQL 8
para filtros, aislamiento, permisos, archivo y restauración, visibilidad
RF-006/RF-009, duplicados, conflicto UUID–SHA y conservación histórica.
Ejecutar mvn --batch-mode --no-transfer-progress -f app/pom.xml verify.
Pendientes de validación manual: Eclipse WindowBuilder Design, dimensiones
reales de pantalla y concurrencia/volumen de producción. El historial
presenta errores registrados por RF-007; la persistencia exhaustiva de
fallos críticos del importador no se modifica en esta revisión.

La conservación documental se mantiene como salvaguarda de los artículos
28 y 30 del CFF; este estado operativo no sustituye obligaciones fiscales
ni representa cancelación SAT.
