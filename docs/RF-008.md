# RF-008 — Validación técnica de XML / esquemas SAT

## Propósito y alcance

Detecta si el XML está bien formado y valida **su estructura** contra el
XSD correspondiente. Identifica por namespace raíz y atributo `Version`:
- CFDI 4.0 — `cfdv40.xsd`
- CFDI 3.3 — `cfdv33.xsd`
- Retenciones e información de pagos 2.0 — `retencionpagov2.xsd`
- Timbre Fiscal Digital 1.1, Pagos 2.0 y Nómina 1.2, de acuerdo con el
  nodo complementario realmente presente en el documento.

Esta implementación admite CFDI tipo **I/E/T/P/N** y retenciones 2.0.
Otros complementos y versiones se declaran `INCOMPATIBLE` mientras no se
incorporen a la lista explícita de XSD compatibles.

**Validación estructural no es validación fiscal integral.** Un XML puede
cumplir XSD sin que su sello, timbrado, cadena original, catálogos temporales,
reglas de negocio, estatus de cancelación o RFC estén comprobados. Estas
verificaciones corresponden a otros RF y no se simulan.

## Esquemas XSD oficiales: instalación local obligatoria

No se incluyen XSD vacíos/sustitutos en el producto. El SAT publica esquemas
con extensas referencias a catálogos, tipos de datos y complementos; por
ejemplo `catCFDI.xsd` contiene varios MiB. Para validar realmente hay que
tener **el esquema completo y todas sus dependencias**.

Repositorio recopilatorio de referencia, que reescribe únicamente rutas
de imports absolutos a relativos:
https://github.com/phpcfdi/resources-sat-xml
Confirmar las versiones frente a la documentación técnica del SAT:
https://wwwmat.sat.gob.mx/cs/Satellite?c=ConsultaInfo&childpagename=SatTyR%2FConsultaInfo%2FSAT_LandingConsultaInformacion&cid=1462241943074&packedargs=d%3DTouch&pagename=TySWrapper

En Linux (incluido Ubuntu), desde la raíz del proyecto:

```bash
bash scripts/instalar-esquemas-sat.sh
```

El script obtiene una revisión fija
`be6963fcb22425dc6055634e0b8dfd5cee50021d` del espejo
`phpcfdi/resources-sat-xml` y la instala por defecto bajo:

```text
~/.visor-cfdi/esquemas-sat/www.sat.gob.mx/
    sitio_internet/cfd/4/cfdv40.xsd
    sitio_internet/cfd/3/cfdv33.xsd
    sitio_internet/cfd/catalogos/catCFDI.xsd
    sitio_internet/cfd/tipoDatos/tdCFDI/tdCFDI.xsd
    sitio_internet/cfd/Pagos/Pagos20.xsd
    sitio_internet/cfd/nomina/nomina12.xsd
    sitio_internet/cfd/TimbreFiscalDigital/TimbreFiscalDigitalv11.xsd
    esquemas/retencionpago/2/retencionpagov2.xsd
```

La herramienta no instala un complemento del SAT ni garantiza que el espejo
se encuentre actualizado a las versiones publicadas posteriormente. La
procedencia y el archivo deben revisarse al actualizar las reglas fiscales.
El script requiere red únicamente para **preparar** el paquete; en operación
normal la validación es totalmente local. También es posible instalar XSD
verificados manualmente desde el portal SAT con la misma estructura de rutas.

Configuración alternativa:

```bash
java -Dvisor.xsd.dir=/ruta/local/esquemas-sat -jar visor.jar
```

Si falta cualquier XSD necesario, la validación no se intenta y se informa
`SIN_ESQUEMA` (jamás `VALIDO`). El esquema XML puede ser erróneo incluso
si es bien formado: se emplean diagnósticos de línea/columna.

## Estados

| Estado | Significado |
| --- | --- |
| `VALIDO` | Documento verificado contra los XSD instalados |
| `INVALIDO` | XML mal formado o incumplimiento XSD |
| `INCOMPATIBLE` | Namespace, versión, tipo o complemento no soportados |
| `SIN_ESQUEMA` | Paquete XSD o alguna de sus dependencias no disponible |
| `ERROR` | Error técnico de E/S o del compilador/validador XSD |

**No se confunde `SIN_ESQUEMA` con `VALIDO`.**

## Seguridad y rendimiento

- Límite de 8 MiB por archivo, 100 000 nodos y profundidad 64 en la
  inspección previa a XSD.
- DTD/XXE deshabilitados, resolución cerrada a rutas locales bajo la raíz
  de esquemas; bloqueo de schemas externos y de `schemaLocation` remotos.
- `Schema` inmutable en caché concurrente; `Validator` y readers por hilo.
- Dos workers, máximo cuatro tareas en vuelo, sin lista global de archivos.
- Lectura de directorios mediante `Files.walkFileTree`, sin seguir enlaces
  simbólicos. Tope operativo de 50 000 XML por ejecución.
- `PanelValidacionTecnica` mantiene únicamente las últimas 500 filas en
  su JTable; el resumen contabiliza el total. SwingWorker evita bloquear
  el EDT. Para auditorías de largo plazo faltará exportación o registro
  histórico en la BD.

## Interfaz y autorización

Navegación: **CFDI → Validación técnica XML / XSD**.
Nuevo permiso `CFDI.VALIDAR_TECNICAMENTE` agregado a RF-003.
La autorización se evalúa nuevamente en backend, no solo en el menú.
El panel tiene constructor sin argumentos, componentes Swing explícitos
y GroupLayout para edición en Eclipse WindowBuilder.

## Decisión de integración con RF-007

**Esta primera entrega de RF-008 es un proceso de validación autónomo de
solo lectura.** NO altera el importador RF-007 ni transforma las importaciones
anteriores en `VALIDO`. Incorporar la validación como paso obligatorio de la
importación exigirá desplegar antes los XSD en todos los equipos y acordar
tratamiento de lotes mixtos, rechazos y trazabilidad.

No se crean ni modifican tablas MySQL ni procedimientos almacenados.
Todavía no se escriben filas en `documento_verificacion`; una siguiente
integración podrá vincular el diagnóstico al documento mediante su UUID/ID
con aislamiento por contribuyente y transacción de auditoría.

## Pruebas

`ValidadorXsdSatTest` prueba el motor con XSD sintéticos e independientes:
XML correcto, XSD inválido, XML mal formado, XXE/DTD, archivo sin XSD,
versión incompatible y ausencia de timbre. **Esas pruebas no certifican
conformidad con los XSD reales del SAT.** Requieren prueba de aceptación con
los XSD descargados y XML de referencia SAT.

Se mantiene pendiente probar manualmente la vista en **Eclipse
WindowBuilder → Design** y efectuar pruebas de carga en hardware limitado.
