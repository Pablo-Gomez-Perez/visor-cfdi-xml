# RF-005 — Administración de terceros

## Objetivo
Administrar contrapartes fiscales de los contribuyentes propios, sin confundirlas
con los contribuyentes de RF-004. Cada contraparte puede tener las funciones
CLIENTE, PROVEEDOR, PRESTADOR y OTRO para cada contribuyente.

## Alcance implementado
- Alta de tercero con RFC nacional o identificación fiscal extranjera.
- Listado y consulta de terceros **por contribuyente autorizado**.
- Modificación de nombre y país fiscal, manteniendo inmutables RFC e
  identificación extranjera.
- Asignación y retirada de funciones comerciales por contribuyente.
- Conservación de terceros y relaciones documentales: no existe borrado físico.
- Bitácora transaccional de cambios administrativos.
- Panel Swing con selección de contribuyente, búsqueda y tabla.
- Diálogo Swing de datos fiscales y funciones comerciales.
- Constructor vacío y GroupLayout para Eclipse WindowBuilder.
- Operaciones de persistencia asíncronas mediante SwingWorker.

## Modelo de datos
Tablas existentes, sin cambios DDL:
- `tercero` (identidad y datos fiscales).
- `contribuyente_tercero_rol` (PK: contribuyente, tercero, función).
- `usuario_contribuyente` (control de alcance por usuario).
- `bitacora_evento` (auditoría).

La misma persona puede tener varios roles comerciales; los RFC genéricos
no se deduplican automáticamente. No se realiza una consulta de vigencia
de RFC ante el SAT ni una verificación de situación fiscal.

## Matriz de permisos RF-003
- `TERCEROS.CONSULTAR`
- `TERCEROS.CREAR`
- `TERCEROS.MODIFICAR`
- `TERCEROS.ASIGNAR_ROLES`

La inicialización incremental de RF-003 registra las nuevas acciones y las
otorga inicialmente a ADMIN, sin reponer permisos revocados previamente.
Las verificaciones efectivas se ejecutan desde `TercerosService`.

## Seguridad
Toda operación exige el permiso de acción y acceso al contribuyente propio.
El permiso `CONTRIBUYENTES.ASIGNAR_USUARIOS` conserva su alcance global
establecido en RF-004. No se permite modificar un tercero compartido si
el usuario no puede acceder a todos sus contribuyentes relacionados.
Tampoco se permite asignar una contraparte ajena a un contribuyente
simplemente adivinando su identificador.

**Limitación arquitectónica heredada:** los clientes Swing con credenciales
MySQL directas pueden eludir controles Java; el aislamiento fuerte entre
clientes no confiables exige un servicio intermedio.

## Validaciones y limitaciones
- RFC: validación estructural, no certificación ante el SAT.
- País fiscal: clave de tres letras, todavía sin catálogo SAT importado.
- No se implementa deduplicación automática por RFC.
- No se implementa importación de CFDI ni sincronización automática de terceros.
- La selección manual de un tercero existente que todavía no esté vinculado
  al contribuyente no está expuesta en el formulario; la API de servicio
  aplica restricciones adicionales de alcance.

## Pruebas y aceptación
Se incluyen pruebas unitarias de normalización y casos inválidos.
La ejecución de Maven y las pruebas de integración MySQL 8 deben
confirmarse en GitHub Actions antes de marcar el requerimiento como terminado.
La apertura de formularios en el diseñador Eclipse WindowBuilder requiere
verificación manual; la compatibilidad no debe darse por comprobada
únicamente por el constructor vacío.

## Dependencias
RF-003 (RBAC) y RF-004 (contribuyentes y acceso por titular).
La rama se creó a partir de RF-004; revisar el estado de integración
de RF-004 antes de fusionar RF-005.
